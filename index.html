Chapter 01
Why this exists

Memory over history.

AIOS does not carry chat history between sessions. Every conversation starts fresh by design, and memory is the system that makes knowledge persist anyway.

The problem

Full history is economically unsustainable.

  • Every response requires sending the full conversation history to the AI model.
  • More history means more tokens consumed per request.
  • More tokens means higher and unpredictable costs at scale.
  • Full-history storage becomes cost-prohibitive quickly.
The AIOS solution

Structured knowledge that persists.

  • Saves only important, structured information, not full transcripts.
  • Reloads curated knowledge automatically in future sessions.
  • No chat history visible in the interface, but key knowledge always persists.
  • Predictable cost structure regardless of conversation volume.

Chapter 03
When to save

Save criteria and
hard exclusions.

Not every piece of context deserves a memory. The system stays useful only when it stores durable knowledge and rejects ephemeral noise.

Save — triggers a memory
A bug is identified and understood.
A process or decision is clarified.
A client detail is confirmed.
The AI makes a mistake and is corrected.
A workflow preference is established.
Don't save — exclude these
Full conversations or transcripts.
Temporary or daily status updates.
CRM-type data (contacts, deals, tasks).
Assumptions or unverified information.
Ephemeral one-off context.
Chapter 04
How to save

Three methods for
creating memories.

AIOS can write memory three ways. Each one has its place, and each one requires your confirmation before a record becomes permanent.

Method 01

Automatic detection

AIOS detects important information during conversation and proactively suggests saving it. No action required, simply confirm or dismiss when prompted.

Method 02

Manual trigger

Explicitly tell AIOS to save something during any conversation.

"Save that to memory"
"Remember that [information]"
Method 03

Correction-based

When AIOS produces incorrect information, correct it and log it as a Correction memory to prevent recurrence.

"That's wrong, [correct info]. Log this as a correction."

AIOS will always ask for your confirmation before permanently saving any memory. You retain full control over what gets stored.

Chapter 06
Best practices

Quality standards for
effective memory management.

Memory is only as good as what you put in. These six practices keep the system clean, accurate, and useful over time.

01
One fact per memory
Keep each memory atomic. Do not bundle multiple facts into a single entry.
02
Be specific
Details outperform vague statements. Client uses AWS us-east-1 with t3.large beats AWS setup.
03
Correct immediately
If AIOS gives wrong information, correct it in the same session and log as a Correction type.
04
Use the right key
Always assign the correct key, client name, global, or person, for proper filtering.
05
Explicitly save important learnings
Don't assume AIOS will auto-detect everything.
06
Review and clean regularly
Outdated memories cause confusion. Audit and remove stale entries periodically.

AIOS doesn't remember conversations.
